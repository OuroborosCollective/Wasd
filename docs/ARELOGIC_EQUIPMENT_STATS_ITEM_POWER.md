# ARELOGIC Equipment Stats / Item Power Contract

**PR:** #1811 Equipment Stats Integration  
**Branch:** `feat/equipment-stats-item-power-contract`  
**Status:** Implemented

---

## 1. Summary

This PR implements the Equipment Stats / Item Power contract that gives procedural loot real gameplay value. Procedural loot items generated by the Loot Machine now have server-authoritative stats that affect combat, gathering, and loot quality.

---

## 2. Why Loot Stats Are Needed Now

Without this PR, the Infinite Loot Machine (#1808) generates beautiful, deterministic loot with Rarity, Affixes, and Social Mutations - but the items had no actual effect on gameplay.

This PR changes that:
- **Sword with +15 attack_power** → increases combat damage
- **Armor with +10 defense** → reduces incoming damage
- **Ring with +50 magic_find** → improves loot rarity chances
- **Tool with +2 gathering_yield** → increases resource yields

---

## 3. Stat Allowlist

All equipment stats are integers only (no floats). The following stats are allowed:

| Stat Key | Type | Cap | Description |
|----------|------|-----|-------------|
| `attack_power` | integer | 100 | Flat damage bonus |
| `defense` | integer | 100 | Damage reduction |
| `max_health` | integer | 500 | Bonus health |
| `max_stamina` | integer | 500 | Bonus stamina |
| `magic_find` | integer | 300 | Rarity weight bonus |
| `gathering_yield` | integer | 5 | Bonus resources per gather |
| `gathering_xp` | integer | 500 | XP multiplier (permille) |
| `loot_quality` | integer | 300 | Affix quality bonus |
| `critical_chance_per_mille` | integer | 250 | Crit chance (0-250 = 0-25%) |

Unknown stats are **fail-closed** - they are ignored by the mapping system.

## 4. Affix → Stat Mapping

The `AffixStatMapping.ts` module maps procedural loot affix stat names to equipment stat keys:

| Affix Stat | Equipment Stat |
|------------|----------------|
| `damage`, `damageMax`, `damageMin` | `attack_power` |
| `armor`, `defense`, `physical_resistance` | `defense` |
| `vitality`, `max_health`, `health` | `max_health` |
| `stamina`, `max_stamina`, `endurance` | `max_stamina` |
| `magic_find`, `mf` | `magic_find` |
| `gathering_yield`, `yield` | `gathering_yield` |
| `gathering_xp`, `xp_bonus` | `gathering_xp` |
| `loot_quality`, `quality` | `loot_quality` |
| `critical_chance_per_mille`, `crit_chance` | `critical_chance_per_mille` |

### Example Usage

```typescript
import { mapAffixToEquipmentStat, mapAffixesToEquipmentStats } from './equipment/AffixStatMapping';

// Single affix
const result = mapAffixToEquipmentStat({ stat: 'damage', value: 15 });
// result.statKey = 'attack_power', result.cappedValue = 15

// Multiple affixes
const affixes = [
  { stat: 'damage', value: 10 },
  { stat: 'armor', value: 5 },
  { stat: 'magic_find', value: 20 },
];
const mapped = mapAffixesToEquipmentStats(affixes);
// Returns [{ statKey: 'attack_power', cappedValue: 10 }, ...]
```

## 6. Aggregation Rules

The `EquipmentStatService.ts` calculates aggregated stats from all equipped items:

```typescript
import { calculateEquipmentStats, createDefaultStatBlock } from './equipment/EquipmentStatService';

const stats = calculateEquipmentStats({
  equipment: playerEquipment,
  proceduralItemStats: lootItemStats, // Map<itemId, stats[]>
});

// Result: EquipmentStatBlock with all bonuses summed and capped
```

### Rules:
1. **Only equipped items count** - inventory items without equipment slots are not aggregated
2. **Starter tools preserved** - Tier 1 tools keep their default 1.0 multiplier
3. **Tier 2 tool bonus** - +1 yield bonus from tier 2 tools (unchanged)
4. **Procedural items via mapping** - Stats come from `proceduralItemStats` Map
5. **Unknown items ignored** - Items not in definitions or procedural map use safe defaults
6. **Deterministic sorting** - Slots are sorted by slotId before aggregation
7. **No mutation** - Source data is never modified

## 7. Combat Hook

The `CombatEquipmentHook.ts` integrates equipment stats into combat calculations:

### Attack Power Integration
```typescript
// damage = baseDamage + equipment.attackPower
const result = calculateFinalDamage({
  baseDamage: 10,
  attackPower: 5,
  defense: 3,
  rngValue: 0.5,
  critChancePerMille: equipmentStats.criticalChancePerMille,
});
// result.damage = 12 (10 + 5 - 3)
```

### Defense Integration
```typescript
// finalDamage = max(1, rawDamage - defense)
const finalDamage = applyDefense(rawDamage, defense);
```

### Critical Chance
```typescript
// critChancePerMille (0-250) converted to decimal (0-0.25)
const critChance = critChancePermilleToDecimal(100); // 0.1 (10%)
```

## 8. Magic Find Hook

The `LootEquipmentHook.ts` integrates equipment stats into loot generation:

```typescript
import { calculateLootEquipmentStats, extendLootContextWithEquipment } from './equipment/LootEquipmentHook';

// Magic find affects rarity weights in RarityResolver
const { effectiveMagicFind } = calculateLootEquipmentStats({
  equipmentStats,
  baseMagicFind: playerBaseMagicFind,
});

// Extend loot context for ProceduralLootMachine
const lootContext = extendLootContextWithEquipment(
  baseContext,
  equipmentStats,
  baseMagicFind,
  baseLootQuality,
);
```

**Determinism:** Same equipment + same event = same loot roll. The magic find value is server-authoritative and deterministic.

## 9. Gathering Hook

The `GatheringEquipmentHook.ts` integrates equipment stats into resource gathering:

```typescript
import { calculateGatheringEquipmentStats, GATHERING_YIELD_CAP } from './equipment/GatheringEquipmentHook';

const { totalYieldBonus, totalXpMultiplierPermille } = calculateGatheringEquipmentStats({
  equipmentStats,
  toolTierBonus: 2, // Tier 2 tool
  toolXpMultiplierPermille: 1200,
});

// totalYieldBonus = (2-1) + equipmentStats.gatheringYield, capped at 5
// totalXpMultiplierPermille = toolMultiplier * (1 + equipmentStats.gatheringXp / 1000)
```

### Yield Calculation
```
base yield = 1
tier 2 tool bonus = +1
equipment gathering_yield = +N
total = 2 + N, capped at 5
```

### XP Calculation
```
base XP * tool multiplier * equipment XP multiplier
100 XP * 1.2 (tier 2) * 1.1 (equipment bonus) = 132 XP
```

## 11. Determinism Rules

1. **No Math.random()** - All randomness comes from DeterministicRng with server seeds
2. **No Date.now()** - Time-based values use server tick
3. **No client values** - Equipment stats are server-authoritative
4. **Fail closed** - Unknown stats/affixes are ignored, not passed through
5. **Caps enforced** - All stats are capped at maximum values
6. **Sorted aggregation** - Items processed in deterministic order (slotId)
