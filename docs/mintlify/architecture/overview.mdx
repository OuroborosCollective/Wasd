# Architecture Overview

Areloria WASD follows a **server-authoritative** architecture with deterministic simulation at its core. This document provides a high-level overview of the system design.

## Core Principles

### 1. Server Authority

All gameplay state follows this chain:

```text
client sends intent
→ server validates
→ server mutates
→ server emits snapshot/event
→ client renders
```

The client **never** authoritatively mutates:
- Inventory or equipment
- Character stats or XP
- Quest state
- Combat or loot
- NPC memory or reputation
- Economy state

### 2. Determinism

Gameplay state must be reproducible from explicit inputs. Simulation code **never** uses:

```text
Math.random()           ❌
Date.now()              ❌
new Date()               ❌
performance.now()        ❌
randomUUID()             ❌
```

Instead, use:
```text
TickId / logicalIndex    ✓
KappaInt / branded types  ✓
StateHash                ✓
DeterministicPrng        ✓
ARE clock/time adapters  ✓
Stable seeds from world facts ✓
```

### 3. 10Hz Server Tick

The authoritative server loop runs at **10Hz** (every 100ms). All systems must declare:

- Cadence
- Maximum work per tick
- Chunk/region scope
- Deterministic seed/time source
- Failure behavior
- Feature flag or registry entry

## Monorepo Layout

```
Areloria-WASD/
├── apps/                    # Application surfaces
│   ├── client-2d/          # Active 2D browser client
│   ├── web/                # Web application
│   └── portal-replit/      # Replit deployment portal
├── server/                  # Authoritative game server
│   ├── src/
│   │   ├── core/           # WorldTick, systems, registry
│   │   ├── networking/     # WebSocket server
│   │   ├── api/           # REST routes
│   │   └── game-data/     # Content definitions
│   └── services/          # Background services
├── packages/               # Shared packages
│   └── shared/            # Types, utilities
├── docs/                  # Documentation (internal)
├── scripts/               # Build, deploy, utility scripts
└── .github/workflows/     # CI/CD pipelines
```

## Runtime Flow

```
Browser /2d Client
  → Host Nginx
  → 127.0.0.1:3001
  → Docker Container
  → Node.js Authoritative Server
  → PostgreSQL / Redis (where enabled)
```
