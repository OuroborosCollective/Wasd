# Server Architecture

The Areloria game server is the **authoritative source of truth** for all gameplay state. Built on Node.js with Express and WebSocket networking.

## Core Components

### WorldTick Scheduler

The `WorldTickScheduler` manages the deterministic 10Hz simulation loop:

```
server/src/core/
├── WorldTickScheduler.ts     # Main scheduler
├── TickSystemRegistry.ts     # System registration
├── WorldTick.ts              # Legacy tick (phasing out)
└── systems/                  # Game systems
```

**Key characteristics:**
- Runs at 10Hz (100ms intervals)
- Systems register with cadence, scope, and deterministic timing
- No unbounded scans in tick
- Feature flags for each system

### System Registry

Systems declare themselves on startup:

```typescript
TickSystemRegistry.register({
  name: 'ResourceGathering',
  cadence: 'everyTick',        // or 'everyNTicks(n)'
  chunkScope: 'observed',      // or 'all', 'none'
  maxWorkPerTick: 50,          // ms budget
  deterministicSeed: 'tickId', // seed source
  featureFlag: 'RESOURCE_SYSTEM',
});
```

### Tick System Context

HTTP routes use `TickSystemContextProvider` for deterministic request context:

```typescript
const ctx = TickSystemContextProvider.getContext(requestId, worldSeed);
const result = ctx.calculate(resourceYield, nodePosition, toolTier);
```

## Networking

### WebSocket Server

`server/src/networking/WebSocketServer.ts` handles client connections:

```typescript
interface ClientMessage {
  type: 'intent' | 'chat' | 'ping';
  payload: unknown;
  clientId: string;
  timestamp: number;
}

interface ServerSnapshot {
  type: 'snapshot' | 'event' | 'delta';
  tickId: number;
  payload: unknown;
}
```

**Connection flow:**
1. Client connects via WebSocket
2. Server assigns client ID
3. Client sends authentication (if enabled)
4. Server streams snapshots at 10Hz
5. Client renders interpolated state

### REST API

REST endpoints provide administrative and informational functions:

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/health` | GET | Server health status |
| `/client-config.json` | GET | Client configuration |
| `/api/admin/content/*` | * | Content administration |
| `/api/manifest/*` | * | State manifest operations |

## Persistence

### Driver Options

```typescript
type PersistenceDriver = 'auto' | 'postgres' | 'file';

// Environment variable
PERSISTENCE_DRIVER=auto
```

**Auto mode:**
- Attempts PostgreSQL first
- Falls back to JSON file if unavailable
- Graceful degradation

## Error Handling

Server errors follow a strict isolation policy:

```typescript
// Failed validation must NOT partially mutate state
try {
  validateIntent(clientIntent);
  executeMutation(intent);
  emitConfirmedSnapshot();
} catch (error) {
  // Revert any partial state
  // Emit error to client
  // Log for debugging
  emitError(error, clientId);
}
```
